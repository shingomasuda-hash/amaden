# 整備報告書【モータ】自動作成システム — UIプロトタイプ

分解整備成績書（手書きPDF）をAIで読み取り、整備報告書（Excel/PDF）を作成するワークフローのUIプロトタイプです。

- 公開ページ: GitHub Pages で `index.html` を配信します（Settings → Pages → Source: このブランチ / root）。
- 社内アクセス: トップページを開くと、まず「合言葉」を聞かれます（後述）。合言葉を通過すると、担当者アカウントを選ぶログイン画面になります。
- お客様ポータル: 案件ごとに「先方用リンクをコピー」（ダッシュボード／案件チャット／管理者画面から）で、`#/customer/<ランダムトークン>` 形式のリンクを発行できます。このリンクは合言葉不要でそのまま開け、その案件の進捗確認・チャットだけができます。管理者画面／案件チャット画面からリンクを無効化・再有効化できます。

## 今のセキュリティレベル（正直な現状）

**これは本番の認証ではありません。** 実際の顧客データを本格的に扱う前に、必ず下の「本物のログイン認証を入れる」まで進めてください。

- **合言葉ゲート**: サイト全体への簡易な足止めです。合言葉はソースコード（`src/app.html` 内の `ACCESS_CODE`）にそのまま書かれており、閲覧者がページのソースを見れば分かります。「知らない人がURLを偶然踏んでも中身が見えない」程度の効果しかありません。
- **ログイン画面**: パスワード入力欄はありますが実際にはチェックしていません（アカウントを選ぶだけで誰でも「管理者」として入れます）。個人を特定してアクセス制御する機能はまだありません。
- **お客様ポータルのリンク**: 案件番号ではなくランダムな16文字トークンをURLに使っているため、他の案件のリンクを推測することはできません。ただしリンク自体を知っている人は誰でも開けます（本来の用途どおり、その先方に個別に渡すリンクです）。
- **データの保存場所**: アカウント・案件・チャット履歴はすべて**閲覧しているブラウザの localStorage**に保存されます。社内スタッフと先方が別の端末を使うと、リアルタイムには同期しません。

### 合言葉の変更方法

1. `src/app.html` 内の `const ACCESS_CODE = "amaden2026";` を新しい合言葉に書き換える
2. `npm run build` で `index.html` を再生成してコミット・push

## 本物のログイン認証を入れる（次のステップ）

GitHub Pages だけでは「本物のGitHubアカウントでログインを制限する」ことはできません。GitHubのOAuthトークン交換はブラウザから直接呼べない（CORS制限）ため、認証を仲介する小さなサーバーが最低ひとつ必要です。データベースを新設せず、最小構成で実現する手順は次のとおりです。

1. **GitHub OAuth App を作成**（GitHub の Settings → Developer settings → OAuth Apps → New OAuth App）
   - Homepage URL / Authorization callback URL に、この GitHub Pages の URL を設定
   - 発行される **Client ID** と **Client Secret** を控える（Secretは絶対に `src/app.html` やリポジトリに直接書かない）
2. **無料の Cloudflare Worker を1つ作成**し、`Client Secret` を Worker の環境変数（Secret）として設定。Worker の役割は「OAuthの認可コードをアクセストークンに交換する」「そのトークンで対象リポジトリのコラボレーターかどうかを確認して結果だけを返す」の2つだけ（20〜30行程度のコードで足ります）。
3. アプリ側（`src/app.html`）に「GitHubでログイン」ボタンを追加し、Workerの結果が「コラボレーターである」場合だけ合言葉ゲートを通過させるように置き換える。
4. 社内スタッフはこのリポジトリ（またはアクセス制御専用の別のプライベートリポジトリ）に **コラボレーターとして招待**しておく。招待されていない人はGitHubでログインしても弾かれます。

この方式であれば、パスワードを一切管理せず、実在するGitHubアカウント＋招待制で本物のアクセス制御ができます。着手する場合は Cloudflare アカウントと GitHub OAuth App の作成（どちらも無料・数分）をお願いします。準備ができれば実装します。

## できること・できないこと（機能面）

- 案件ごとのチャット・履歴、先方ポータル、管理者画面のアカウント管理・変更履歴・CSV出力は動作します（ただし上記の通りブラウザ内保存です）。
- 先方ポータルの「AIエージェントでの操作について」パネルは、案件ごとに管理側で許可した場合のみ表示され、ブラウザで動くAIアシスタント（例: Claudeなどのブラウザ拡張）がページ構造から操作対象を認識しやすいよう、操作候補をリスト表示しているだけです。AIが実際にサイトの中身（デザインや項目）を書き換えられるようにするには、別途、権限管理を伴う編集APIの設計が必要です。
- OCR・Excel出力・PDF生成・フォルダ保存は未接続のモックです。

## 開発

ソース（人が読み書きする版、CDN参照）は `src/app.html` です。ここを編集し、ビルドすると
`index.html`（React/ReactDOM/Babelを埋め込み、TailwindのCSSを事前コンパイルした、CDN不要の単体HTML）が生成されます。

```bash
npm install
npm run build
```

`index.html` は GitHub Pages がそのまま配信できる、外部リクエストなしで開ける単一ファイルです。
